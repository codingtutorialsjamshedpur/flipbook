3. P1 — UNIFIED SPEECH-TEXT NORMALIZATION FOR TTS
============================================================

3.1 Protect the original document
Create a separate speech-normalization layer. Never permanently delete punctuation/symbols from the original stored document or rendered content. The reader should display the original content; only the text sent to TTS should be normalized.

The same normalization rules must apply to extracted PDF text, OCR text, TXT, DOCX, EPUB and pasted text. The normalization output must retain a source-offset map from spoken tokens to the original content so word seeking and karaoke remain accurate.

3.2 Decorative/formatting symbols must not be spoken
Do not pronounce formatting and decorative symbols as literal names in ordinary prose. Examples include:
- Markdown emphasis markers: *, **, _, __, backticks where used as formatting.
- Decorative dash/hyphen separators.
- Decorative underscores.
- Bullets or repeated symbols used only for formatting.
- Unnecessary markup delimiters.
- Non-semantic decorative symbols.

For example, when punctuation acts only as a separator, “cat-mouse” should be spoken approximately as “cat mouse”, not “cat dash mouse”. Do not announce “asterisk”, “underscore”, “hash”, “backslash” or “dash” in ordinary prose merely because the character appears in the source.

Do not indiscriminately remove meaningful punctuation or destroy sentence boundaries. Periods, commas, question marks, exclamation marks and paragraph boundaries may be converted into natural pauses. Preserve the original visible text.

3.3 Numeric operator rules
Use context-aware normalization: a special character directly adjacent to digits may be a unary or binary operator, a ratio/fraction separator, or a numeric range rather than decorative punctuation.

At minimum implement and test:
- “5/10” → spoken naturally as “five out of ten” in a score/ratio context, per the requested default.
- “5÷10” → “five divided by ten”.
- “5\10” when used as a numeric separator → normalize as a division/fraction expression and speak naturally; by default use “five out of ten” for a ratio-like expression unless the context marks it as arithmetic.
- Other fraction/division slash forms, including a fraction slash, should use the configured semantic rule rather than saying “slash”.
- “5 + 2” → “five plus two”.
- “5 − 2” or “5-2” when clearly arithmetic → “five minus two”.
- A leading negative sign in “-5” or “−5” → “negative five” (or the configured equivalent), not “dash five”.
- A numeric range such as “5–10” → “five to ten” when a range is the intended meaning.
- An operator between two numbers must be interpreted as an operator according to its type; do not read the operator's glyph name.

Use an explicit tokenizer/normalizer with unit tests. Do not assume every symbol between numbers has the same meaning. Where meaning is ambiguous, apply documented defaults and support a future configurable pronunciation rule.

Treat symbols between ordinary words as formatting/separators when appropriate, while preserving meaningful terms and domain-specific notation. For example, “cat-mouse” should not cause “dash” to be spoken. Do not damage email addresses, URLs, source code or mathematical expressions if the app has an explicitly configured mode for reading those content types; ordinary prose is the default normalization mode.

3.4 Source mapping
Every normalized spoken token must map to its original source range where possible. A word-seek tap on the visible document must locate the correct normalized spoken token even if its adjacent characters have been removed from TTS text. Normalization must never shift word indexes unpredictably.
